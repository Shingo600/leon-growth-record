# おでかけ機能の初回設定

UI画像を作成してから実装した、独立型の追加機能です。アプリ内の「おでかけ」タブで使います。
既存の成長記録・食事・活動の保存形式は変更していません。

## 1. Supabaseに保存先を追加

1. いつものSupabaseプロジェクトを開く。停止中なら先に再開する。
2. SQL Editorで新しいクエリを開く。
3. `supabase/migrations/20260928_outings_addon.sql` 全文を実行する。
4. 成功したことを確認する。エラーが出たら、追加の権限開放はせず内容を確認する。

追加するものはお気に入り・日次利用回数の2テーブルと2関数のみです。既存の `app_snapshots` は変更しません。
匿名アクセスは許可せず、家族の同期コードを検証したサーバーからのみ使います。
このSQLには既存の日記データを消す処理はありません。権限を取り消す `revoke` は新しい機能のテーブル・関数が対象です。

## 2. Vercelに設定を追加

プロジェクトの Environment Variables に以下を追加します。既存の4項目はそのまま残します。

| 名前 | 値 | 備考 |
|---|---|---|
| `OPENAI_API_KEY` | OpenAIで発行したAPIキー | SensitiveをON。チャットやGitに貼らない |
| `OUTINGS_ADDON_ENABLED` | `true` | `false` にすればAI検索を停止できる |
| `OUTINGS_AI_MODEL` | `gpt-4.1-mini` | 省略時も同じモデル |
| `OUTINGS_DAILY_LIMIT` | `10` | 家族全体の1日上限。1から100の整数 |

本番はProductionを対象にします。Previewも使う場合、同じキー・DBを共有すると検索回数とお気に入りも共有されます。
キー名に `NEXT_PUBLIC_` は付けません。値の前後に空白や改行が入っていないか確認してください。
OpenAI APIの利用設定が必要です。ChatGPTの月額契約だけでAPIが無料になるわけではありません。

## 3. 公開・動作確認

1. この変更をVercelにデプロイする。環境変数を後から追加した場合はRedeployする。
2. アプリを開き直し、下部メニューを横にスクロールして「おでかけ」を開く。URLは既存ドメインの `/outings`。
3. 必要ならいつもの家族共有コードを入力する。
4. 地域とジャンルを選んで1回検索し、出典リンクの施設名・犬同伴条件を確認する。
5. 保存すると「行きたい」に追加される。メモ編集、再読み込み後の保持、別端末での共有を確認する。
6. OpenAIの利用状況で検索込みの料金を確認する。

地図・Places・別契約の検索サービスは使いません。ただしOpenAIの生成料金とWeb検索ツール料金がかかります。
日次上限は金額上限ではありません。タイムアウトや不正な回答でもAI側で課金される可能性があるため、検索開始後の利用回数は戻しません。自動リトライもしません。
時刻の区切りは日本時間の午前0時です。画面を開く・条件変更・お気に入り閲覧ではAI通信しません。
検索結果のURLは検索ツールの出典と突き合わせますが、情報内容の正確性までは保証できません。施設の最新条件はリンク先で確認します。

## バックアップと停止

- 「行きたい」内の「おでかけのバックアップ」からJSON出力・復元できます。通常の日記バックアップとは別です。
- 復元は追加・更新で、同じURLのメモは復元内容に変わります。上限200件を超える場合、変更全体を中止します。
- オフラインでは端末に残ったお気に入りのコピーを閲覧できます。変更・検索には通信が必要です。
- `OUTINGS_ADDON_ENABLED=false` に変更して再デプロイすれば検索だけ停止できます。保存済みの場所は消えません。

## 開発時の確認

```powershell
node tests/outings.cjs
npm run build
```

UIのみの検証は、ビルド後に別ターミナルで次を実行します。

```powershell
npm run start -- -p 3010
node tests/outings-preview.cjs
```

`http://127.0.0.1:3011/outings` は架空データの検証画面です。AI・DBには接続せず、お気に入りはプロセス終了で消えます。
この検証サーバーは本番コードから参照せず、ループバックだけで待ち受けます。本番では起動しません。

自動テストでは認証、入力・URL検証、出典対応、利用制限失敗時の停止、二重実行防止のAPI分岐を確認します。
本番SupabaseでのSQL実行、実際の並行リクエスト、AI検索品質・請求額は設定後の確認事項です。
